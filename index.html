This website is a working AWS infrastructure project. I adopted the existing environment into Terraform, replaced fixed resource IDs with references, and migrated local state to a dedicated S3 backend.

Ez a weboldal egy működő AWS-infrastruktúraprojekt. A meglévő környezetet Terraform-kezelésbe vettem, a rögzített erőforrás-azonosítókat hivatkozásokra cseréltem, majd a helyi állapotot külön S3-backendbe migráltam.

Route 53 resolves the domain; CloudFront serves requests and fetches origin content through OAC. DNS does not proxy HTTP traffic.

A Route 53 feloldja a domaint; a CloudFront kiszolgálja a kéréseket és OAC-val éri el a forrást. A DNS nem továbbít HTTP-forgalmat.

What I implementedAmit megvalósítottam

  • Private S3 origin with public access blocked; signed CloudFront requests through OAC.
  • Privát S3-forrás blokkolt nyilvános hozzáféréssel; OAC-val aláírt CloudFront-kérések.
  • HTTPS through ACM, Route 53 aliases for IPv4 and IPv6, and AWS WAF managed rules.
  • HTTPS ACM-tanúsítvánnyal, Route 53-aliasrekordok IPv4-hez és IPv6-hoz, valamint AWS WAF kezelt szabályok.
  • 25 managed resources, including a separate encrypted, versioned state bucket with native S3 locking.
  • 25 kezelt erőforrás, köztük külön titkosított, verziókövetett állapottároló natív S3-zárolással.

How I verified itÍgy ellenőriztem

  • Validated Terraform configuration and confirmed a no-change plan after state migration.
  • Terraform-konfiguráció ellenőrzése és változtatás nélküli terv igazolása az állapotmigráció után.
  • Used Linux DNS and HTTP tools to inspect resolution, CloudFront responses and origin error handling.
  • Linuxos DNS- és HTTP-eszközökkel vizsgáltam a névfeloldást, a CloudFront-válaszokat és a forráshibák kezelését.
  • Reviewed changes on Git branches and merged the configuration and documentation into main.
  • Git-ágakon ellenőriztem a változásokat, majd a konfigurációt és dokumentációt a main ágba egyesítettem.
